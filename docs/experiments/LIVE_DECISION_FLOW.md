# E41: persisted live credit decisions (engineering)

Rules fixed on 19 October 2026 before implementation. This is integration work, not a scored experiment or a new accuracy/alpha claim.

1. Use already-scored live rows from the same `/analyze` callback and linker. Preserve supplied event, impact, per-company sentiment, role and model/path metadata; never call another scorer. Older rows without entities retain their supplied headline score.
2. Call the existing `gate()` with the configured trigger, the same live linker and `precision_rules=True`. Keep its code, categories, thresholds and reasons unchanged. Gate the available scored context in publication order; a corroborating text must already precede the candidate's timestamp under the gate's own rule.
3. Fired rows get a dry-run Module B capital/loss preview using the existing revaluation and stored SEC book, default COVID episode, configured flat/scaled multiplier and rates. Show the book date and assumptions. Outside-book obligors or missing inputs produce an error, not invented exposure. Module A explicitly reports `no change`; no execution, weights, book or historical output is modified.
4. A key is SHA-256 of canonical JSON containing whitespace-normalised, case-folded text, ticker, event, UTC publication minute, effective-config hash, combined model-file hash and book-file hash. One terminal `decided` or `skipped` result per key, including after restart. URL changes alone do not create another decision. Configuration/model/book changes deliberately create a new context/key.
5. Append attempts to `data/live/decisions.jsonl`; append the full decision first to a **separate** hash chain, `data/live/decision_ledger.jsonl`, then its index row with the ledger hash. Both are ignored by Git. Reconcile a ledger append whose index write was interrupted before computing another preview. Use same-host advisory file locks and fsync. The historical ledger format and `chain/build/verify` behaviour stay unchanged; its stored file is never written.
6. Status is `decided` (gate fired and preview succeeded), `skipped` (gate did not fire, with reason), or `error` (with message). Errors may retry once per subsequent processing pass; successful/skipped keys do not rerun. Restore pending/error work from persisted scored rows and decision records. Catch failures so ingestion continues; surface disk/ledger failures in health. Do not silently ignore malformed or edited persisted records.
7. Record the full scored input and its SHA-256, effective config/hash, model files/hashes, book hash, code Git revision (or `unknown`), code-file digest, gate reason, attempt count and timestamps. Missing provenance is explicit; do not present a hash of a model name as a model-file hash.
8. Historical signals, outputs, labels, models, frozen evaluation/rule docs, batch pipeline, replay and Module A/B history remain byte-identical. Tests compare protected-file hashes before/after invented-row processing. A separate dry replay check reads a few existing rows without rescoring and compares the same-row gate decisions.
9. `live_decisions=false` is the default. Off means no decision or live-ledger files are written. `/analyze` remains unchanged. Only the live poll path invokes the opt-in flow; no human approval step or trading endpoint is added.
10. `/live/health` reports last poll/success, newest-item age, source freshness, median/max ingest-to-decision lag for the last 100 decisions, errors, pending/backlog, and recent actual scoring models/paths. Missing values carry reasons. Precision, ECE and confidence are `not available`: no live labelled reference is supplied.

Limits: one GDELT source with DOC/GKG delivery modes, observation timestamps rather than verified publication times, bounded cached context, an old hypothetical book and scenario assumptions. Earlier E36b precision is seen design-data evidence. Preview is not a forecast or execution. Local append/hash checks are tamper-evident relative to the retained chain, not externally anchored proof against a full rewrite/truncation. Locks and journal recovery cover cooperating processes on one host/local filesystem, not a distributed transaction service. Disk corruption/partial writes stop decision work visibly while the feed can continue. Nothing here adopts Laya or the extended linker.

## Implementation and checks

Implemented in `live_decisions.py`, with a poll hook, `ledger.append()` and `/live/health`. The flag remains false. To enable locally, set `live_decisions=true` and restart the API so the scoring configuration/linker and decision context are built together. `GET /live/health` is read-only; `/live` or `/live/refresh` starts the normal feed. With the combined site, API paths have the `/api` prefix. Recent health decisions include the preview object and ledger hash; the full records are in the ignored live files.

Source freshness uses a declared heuristic: newest cached observation at most twice the poll interval old. It is not a publication-latency guarantee. Model hashes describe configured local files at decision time; old cached scores do not acquire retroactive proof of their in-memory weights. A local FinBERT file manifest is unavailable in baseline mode, so that combination reports a provenance error instead of downloading or inventing a model-file hash. Current local own/entity models have file manifests. Existing cached rows without path metadata show an explicit missing reason.

Invented-row tests exercise successful/skipped/error records, error retry without new news, persisted unprocessed scores, recovery after a ledger commit/index-write interruption, original corroboration surviving cache eviction, two cooperating instances, edited/partial journals, supplied entity scores/roles, E36b/severity reuse, disabled writes and protected-file hashes. A four-row stored replay dry check matched `/gate` on all four rows (two previews, two skips), verified the chain and added zero decisions on restart. It did not run NLP or change historical outputs. Journal paths in that check were temporary; a private verification record is kept with the task log. No new predictive result is claimed.

Verification: 25 new invented-row tests; 52 focused integration/regression checks; full offline suite 1,057 passed and one expected failure, Ruff clean. All 303 protected-file SHA-256 values, the stored-output inventory, 99 model-file sizes/mtimes and the exact `/analyze` function source remained unchanged. Actual live network ingestion was not run for this task.
